# Graph lifecycle

Start with `$axsk build` for the resolved registered project, then `$axsk watch`
for authorized automatic refresh. The engine owns inventory, analysis, relationship
resolution, validation and publication. The skill never writes graph nodes/edges.
Watch is instance-wide; inspect every registration, reuse the authorized daemon
and keep shared services running. Polling is reported as polling.

Ask code questions through `$axsk ask ...` and hypothetical removal reviews through
`$axsk impact ...`. Discover MCP schemas, confirm authenticated read scope, search,
resolve node identity, request bounded relations and read returned source spans.
Duplicate symbols require disambiguation. Empty, stale or truncated results do not
prove no impact. Dynamic/reflection and consumers outside scope remain limitations.

`$axsk export this graph` keeps the current project/node selection and generation
context, verifies one pinned catalog vector and writes JSON (optional HTML). It does
not rebuild, alter Git index or claim staged-source fidelity from a live generation.
Checkpoint source-selector verification is an explicit advanced export request.

`$axsk doctor` diagnoses; `doctor upgrade` plans/delegates to `$axsk update` with
existing exact approval, stale-plan refusal and rollback checks. `$axsk version`
reports installed/offline/not_checked facts. Refresh and software/schema update are
different operations.

Read engine cycle records for measured processing durations and before/after
source generations. Unknown phases/queue/detection metrics are null with reasons;
a hook/client wait is not engine processing time. Idle does not imply completed work.
