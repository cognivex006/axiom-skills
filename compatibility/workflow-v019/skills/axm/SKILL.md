# Axiom ecosystem lifecycle

Resolve the requested target and existing installation first. Read the relevant
workspace/repository instructions and installed policy. This skill grants no
permission and does not widen host controls. Installed consumers need no private
specification checkout or contributor task cards.

- Install/setup or explicit repair: load [installation](references/installation.md).
- Update/upgrade: load [upgrade](references/upgrade.md).
- Diagnostics/version: inspect actual `axm --help`, `axm version` and `axm doctor`;
  diagnosis is read-only. Graph/MCP diagnosis can hand off to axge doctor.
- Removal: use the installed `axm uninstall` plan/consent flow; preserve user data,
  source and unrelated files. Never delete an old installation tree manually.

Inspect installed capabilities and the selected target's verified artifact metadata.
Lifecycle mutation binds the reviewed exact plan, scope and installed state. Existing
authorization persists; request a missing approval only at the actual mutation
boundary. Never fabricate an approval digest or silently replan/apply after drift.
Explicit unattended installation can use its documented noninteractive option.

Report actual component versions, artifact hashes, target, plan/apply/health/rollback
results and any unverified leg. A printed plan is not an applied update. Missing
entrypoints, unsupported targets, offline checks and NotReady are reported as observed.
One updater/installation engine owns the transaction; skills never download or install
a second implementation. Feature development in this repository is not a release.
