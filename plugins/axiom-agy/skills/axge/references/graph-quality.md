# Graph quality and measured outcomes

JSON Schema defines compatibility; graph JSON is derived source data; export/render
is a selected artifact. Build/watch never invent a schema or manually edit generated
nodes/edges. Structural validation includes schemas, IDs/references, hashes, manifests
and catalog vectors. Semantic evidence includes supported constructs, source symbols,
coverage denominator, unresolved/inferred relationships and selected source samples.

Schema-valid is not semantic accuracy. No edge is not no impact. Only a gold dataset
with actual numerator/denominator supports precision/recall claims; report dynamic,
reflection, generated-code and out-of-scope blind spots. Malformed, unsupported,
empty, stale and truncated results cannot become a successful complete graph claim.

Build/watch processing_ms is a monotonic duration inside the engine. Each actual
work cycle carries outcome, changed/analyzed files and before/after generations.
Queue/debounce, scan/analyze/validate/publish and source-observed delay are distinct;
uninstrumented fields are null with reasons, never fabricated zeros. A client wait
or hook elapsed_ms is not engine processing time. Pending/client timeout is not
completed server work. Durations never alter deterministic graph hashes. Idle
fallback inventories do not constitute successful changed-source cycles.
